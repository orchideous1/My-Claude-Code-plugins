# 工作流定位

本提示用于 `summarize` 工作流 **AUDIT** 阶段的独立 sub-agent。

主代理已完成 REVIEW → ALIGN → EVALUATE → PACKAGE → ARCHIVE，并已将 guide 归档。AUDIT 与前面的回顾/对齐/评估在上下文上解耦：sub-agent 不应依赖主代理的对话历史，只能基于下面列出的材料进行审查。

## sub-agent 可见材料

sub-agent 只能看到以下材料，不得向主代理索要额外上下文：

1. 本次会话的 `session.md`、`plan.md`、guide 文件（`handoff.md` 或 `architecture.md`，如已归档则使用 archive 中的副本）。
2. 本次会话涉及的代码变更（`git diff`）。
3. 项目级 `CLAUDE.md`。

## 审查任务

请对以下五个方面进行独立审查。如发现目标偏差、架构理解问题或文档冲突，向用户提出需要重新对齐的问题。

### 1. 提示词合理性

- 当前会话是否暴露出现有 prompt 模板的问题？
- 是否有 prompt 过于冗长、模糊或与实际流程脱节？
- 基于本次会话，能否归纳出可复用的通用提示或检查项？
- 建议哪些 prompt 需要新增、删除或重写？

### 2. 文档冲突

- `CLAUDE.md` 与 skill 文档（`skills/*/SKILL.md`）是否存在矛盾？
- 提示模板是否引用了已废弃的文件路径或阶段名称？
- 状态文件格式要求在不同文档中是否一致？

### 3. 状态架构

- 状态文件是否按约定存放在正确位置？
- YAML frontmatter 是否完整、一致？
- 是否存在冗余状态文件或缺失的关键状态文件？
- 中间状态、归档产物、长期记忆的边界是否清晰？

### 4. `CLAUDE.md` 优化

- 本次会话中的经验、约束或规则是否应沉淀到 `CLAUDE.md`？
- 现有 `CLAUDE.md` 是否有表述不清或与实际操作冲突的地方？
- **仅输出修改建议，不要自动写入 `CLAUDE.md`**。若用户同意，后续应由 `build` 流程执行。

### 5. 归档内容审查

- 本次会话是否产生了值得归档的 guide？
- `handoff.md` / `architecture.md` 内容是否准确、完整、无敏感信息？
- 根据 workflow 类型，归档文件名是否符合命名规则？
- guide 是否过度简化？是否保留了足够的过程信息供新会话接手？

## 输出格式

将发现按「阻塞 / 建议 / 通过」分类输出，**不要写入任何文件，也不要进入 archive**。

```
## 审查结果

### 阻塞
- [ ] ...

### 建议
- [ ] ...

### 通过
- 提示词合理性：通过 / 部分通过
- 文档冲突：通过 / 部分通过
- 状态架构：通过 / 部分通过
- CLAUDE.md 优化：通过 / 部分通过
- 归档内容审查：通过 / 部分通过
```

## 约束

- **不得写入任何文件**，包括 `CLAUDE.md`、状态文件、guide 文件或 archive。
- **不得修改主代理或项目代码**。
- 如认为主代理存在目标偏差，可在「阻塞」中提出重新对齐的问题，由主代理向用户转达。
- 审查结果只返回到当前对话，由主代理向用户展示。
